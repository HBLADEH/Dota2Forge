供[AstrBot README](../../adapters/astrbot_plugin_dota2forge/README.md)和[Dota2UID README](../../adapters/Dota2UID/README.md)展示当前功能。两端使用共享 Renderer，公共卡片从任意一端采集一套即可，另一端复用时标明来源；平台配置页分别采集。旧版主宰出装原图保留为历史示例，见[来源记录](../assets/screenshots/README.md)。

## 第一批：功能展示

建议提供以下 **7 张卡片**。GsCore 使用 `do…`；AstrBot 示例使用 `/do…`，按实际唤醒前缀调整。优先提供脱敏后的 Bot 原始 PNG，可另附包含命令和回复的聊天截图。

| 文件名 | 操作 / 命令 | 保留内容 |
| --- | --- | --- |
| `menu.png` | `do菜单` | 完整帮助卡、品牌、命令和底部提示，展示当前“远古锻炉”主题 |
| `player.png` | `do查询` 或 `do查询 <ID>` | 玩家概况、段位徽章、预估 MMR 区间或下界、非精确说明、来源与时间 |
| `recent.png` | `do战绩 10` | 第一页五场：绝对序号、胜负、英雄、KDA、GPM/XPM、开始时间/时长、来源及翻页提示；当前战绩卡不含装备 |
| `match-overview.png` | `do比赛 <比赛ID>` 或同会话 `do比赛 第1场` | 比赛总览、胜方、时长、十人对比、IMP与表现依据、团队优势曲线及来源说明 |
| `match-radiant.png` | 同一次比赛查询的天辉页 | 五人详情、等级/补刀/经济/伤害等指标、装备/背包/中立槽、缺失说明 |
| `match-dire.png` | 同一次比赛查询的夜魇页 | 与天辉同一场比赛的另一队详情，保留完整页脚 |
| `hero-items.png` | `do主宰出装`，也可选其他英雄 | 出门/前期/中期/后期四组物品名与购买次数、未知样本说明、OpenDota 来源与时间、热门不等于最优说明 |

比赛报告按标准十人比赛返回总览与两队详情，建议选来源字段较完整、确有 IMP 和优势曲线的正常对局。缺失时保留真实说明，不填造数据。三页来自同一次查询，无需拼成超长图；报告原图宽 1600px，保留原分辨率，README 中可分别展开。

## 可选补充

- **账号绑定**：`do绑定 <ID>` 成功提示与 `do账号` 卡，账号和聊天身份脱敏。
- **分页交互**：同一会话先 `do战绩 20`，再 `do战绩 第3页`，保留取页命令与返回。
- **文字模式或缺失数据**：已有真实场景可补充，不必专门制造失败。
- **订阅展示**：用户自行创建订阅，提供订阅列表或真实收到的新比赛/日报通知；未验收前不作为已成功推送示例。玩家订阅首次只建立基线，不补发旧战绩。

README 优先展示第一批卡片，不要求将所有可选图放入首屏。

## 拍摄与脱敏

1. 使用当前已安装版本。随图注明原宿主、宿主版本、插件版本、日期；如知道 Renderer 版本也一并记录。旧版卡片标明版本，不用于展示新主题。
2. 只保留相关命令与 Bot 回复，裁掉无关聊天。遮盖昵称、头像、账号 ID、群号/会话标识、私人路径和 Token；比赛 ID 与命令里的 ID 同样处理。
3. 比赛图中其他玩家的身份也须处理。保留英雄、装备、统计、时间、来源和“未知/预估/不完整”等说明；遮挡只处理隐私字段，不改写结果。
4. 使用 PNG 和原比例，普通卡片原宽 780px、比赛报告原宽 1600px。不要拍摄屏幕照片、加滤镜或压缩为长图缩略图；脚注不可裁掉。
5. 仅提供最终脱敏版本；原始图留在本机。配置图不要包含整份真实配置文件，密码输入框之外的地址/路径也需检查。

## 收图后处理

按内容和当前版本审查图片，嵌入对应 README，并标明跨端复用来源。新增源图按真实宿主或有来源记录的共享日期目录存放，未知宿主须明确说明，不覆盖历史原图；同步[来源记录](../assets/screenshots/README.md)、发行白名单、本地链接、摘要与 ZIP 大小检查。不自动扫描原始截图目录。

截图仅证明所展示的画面；命令捕获、权限、其他平台与主动推送等实机验收继续按[宿主](astrbot.md)及[订阅任务](../../.agents/tasks/active/2026-10-02-subscriptions.md)分别记录。
