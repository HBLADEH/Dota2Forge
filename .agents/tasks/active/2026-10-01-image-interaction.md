# 图片菜单与基础查询回复

Status: planned

## 目标
在已验证的 Dota2UID QQ 闭环上，实现以图片为主的帮助菜单、玩家概况、近期战绩和账号状态交互，参考 StarRailUID 的命令 → 数据 → 卡片 → 图片发送方式。

## 非目标
首个切片不新增单局详情/IMP/经济数据、按钮回调、订阅、自动重试或跨源回退。图片中的菜单项是命令说明，点击交互需后续平台能力验证。

## 验收
- [ ] 先确认合成数据样图、字体、主题、手机可读性和每页条数，再进入实现；菜单只列已启用功能，管理员项按可信权限控制。
- [ ] 规划独立共享包 dota2forge-renderer（导入 dota2forge_renderer），不依赖平台 SDK；Core 领域/用例不依赖绘图库或浏览器，两个适配器共用渲染结果。
- [ ] 以 Pillow 完成 MenuCard、PlayerCard、RecentMatchesCard，账号状态/操作结果逐步补充 StatusCard；错误和必要提示保留可读文本。
- [ ] dota菜单/dota帮助 返回分类图片；dota玩家 返回昵称、段位及来源/时间；dota战绩 保留 1–100 默认 10，按合适条数分页出图，展示比赛 ID 及详情查询方式。
- [ ] 使用北京时间并标明时区，时长为分钟/秒，英雄使用可验证中文名和图标；维护版本化资源目录、来源/授权与缺图占位，未知英雄保留 ID。
- [ ] 不把 None 画成零，0/False 有效；段位可下降，不承诺精确 MMR/完整历史，区分抓取时间与未知观测时间。
- [ ] 渲染接收结构化数据与本地资源，不发 Provider 请求；绘制/编码经工作线程并限制并发、尺寸和文件大小，取消/停用仍可关闭资源。
- [ ] 规范文本/图片回复类型及渲染失败回退；回退使用同次成功查询的文本，不二次请求、不吞数据源失败，发送失败不得盲目重复发送。
- [ ] 先接 Dota2UID 并实机验证图片发送、压缩、分页、重载；AstrBot 后续消费相同卡片能力。新增包时更新锁定/构建/生成参考及治理路径，治理改动须维护者评审。
- [ ] 禁网合成测试覆盖长昵称、中文字体、未知字段、无战绩、超量分页和缺资源；视觉 QA 检查裁切/重叠，真实单会话验收另列且不入库聊天截图。
