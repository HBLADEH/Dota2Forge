# Dota2Forge 全主题重设计提案

2026-10-11，供用户先看方向与样图。仅完成设计与离线预览，尚未改动生产 Renderer、两端插件配置或发行包。所有统计均为合成数据；不是实机聊天截图。

## 从项目现状出发

这是 Bot 图片与文字回复系统，主要界面是菜单、玩家、战绩、比赛报告、热门出装和状态提示。两端共享同一 Renderer，GsCore 标识 Dota2UID，公共品牌 Dota2Forge。不要为本次重设计假设一个已存在的独立网页后台。

以[当前 Renderer 契约](../../../docs/subsystems/renderer.md)、[报告决策](../../notes/implemented/2026-10-09-match-analysis-report.md)及代码核对现状：查询、段位预估、近期分页、按 ID / 序号比赛报告、STRATZ IMP、优势曲线、热门出装与订阅消费者已有实现。README 部分早期段落的“IMP 尚未实现”已被上述新决策替代。真实订阅推送、不同宿主权限与客户端压缩不能由离线样图证明，仍按各自 active 任务验收。完整英雄攻略、AI 分析、回放与地图结论不放进已实现菜单。

## 推荐方向：远古锻炉

参考 [Dota 2 官网](https://www.dota2.com/home)的深暗背景、大标题、克制红色强调与英雄视觉；参考[官方英雄页](https://www.dota2.com/hero/juggernaut)的角色识别入口。以下取舍是本项目设计判断：保留远古石材、暗金属和锻造气质，把文字和数据区做得平静、清晰。

- 石材／遗迹只放在标题背景；正文用低纹理实色，不把火焰、粒子或英雄绘画铺在数据背后。
- 品牌字标采用少量衬线气质；中文标题和正文用完整 Noto Sans CJK SC，数字对齐，长名称换行而非任意缩小。
- 炭黑 `#101216`、面板 `#1B2025`、内嵌 `#242A30`、正文 `#E8E3D8`、说明 `#ADB1B6`。
- 铜金 `#C0A777` 用于品牌、命令和重点经济值；余烬红 `#ED7865` 用于失败／夜魇；天辉绿 `#92C6A2` 用于成功／天辉；蓝灰 `#9AB9D1` 用于信息提示。状态始终配文字。
- 4px 方切边和少量1px分隔，避免每项都套框；不采用玻璃透明、霓虹紫蓝、大圆角、花哨 HUD 或装饰性评分。
- 常规图片780px、最多1800px、2MiB；报告1600px、最多3200px、2MiB，沿用现有上限。常规正文26–32px，关键数字36–60px，来源说明24px起；缩到390px检查。宽报告保持全量，允许放大阅读，不删字段迎合手机比例。

比较过三个方向：远古锻炉兼顾主题与长期阅读，推荐；以天辉青绿为主的石庭方向比较轻，但弱化品牌锻造特征，可作为后续可选配色；以夜魇红黑为主的强烈方向适合宣传横幅，整张战报长期使用容易让所有数据像告警。首轮只细化推荐方向，其他配色尚未制作样图。

## 组件覆盖与信息顺序

| 范围 | 重设计方式 | 直接说明／下一步 |
| --- | --- | --- |
| 普通菜单 | 用查段位、查战绩、看比赛、找出装四个目的组织；绑定、账号管理、订阅靠后 | `do查询`、`do战绩`、`do比赛 第1场`、`do主宰出装` |
| 管理员菜单 | 公共菜单后的管理附页，按真实权限和启用状态展示；完整进阶命令保留 | 停用、核心状态／安装／更新、素材管理、订阅重试，按宿主实际支持列出 |
| 绑定／账号卡 | 先说已绑定／未绑定，账号与改绑／解绑放第二层 | “现在输入 do查询”／“输入 do绑定 <ID>” |
| 玩家卡 | 昵称、真实段位徽章、段位文字、预估区间、下一条命令 | “按段位区间估算，非精确 MMR”；未知不估算 |
| 近期战绩 | 五场完整分页；英雄、胜负、KDA、GPM、六装备，保留绝对序号及详情入口 | `do战绩 第2页`、`do比赛 第1场`；比赛ID／开始／时长在实施时保留 |
| 比赛总览 | 胜方和比分优先；天辉／夜魇十人对比、两条优势曲线、IMP正负列表和统计依据 | 按现有总览＋两队三页发送，不画未实现的页签按钮 |
| 队伍详情 | 一名参赛者一个完整区块；五人、所有已实现指标、六装备／三背包／中立槽 | 正物品缺图保留名称／ID；空槽不放“空”字 |
| 旧详情卡 | 沿用同一标题、阵营色、指标和装备槽组件，维持兼容入口 | 保留身份匿名／未知、解析状态、来源与时间 |
| 热门出装 | 四阶段标题＋前五项图标、两行名称、购买次数 | “热门不等于最优；次数不是胜率或购买顺序” |
| 订阅通知／日报 | 结果→比赛／日期范围→统计→来源；订阅ID／事件ID靠后但保留 | 默认关闭、有限观察、人工重试可能重复；真实投递继续单独验收 |
| 成功／空／缺失／错误 | 两层提示：发生了什么＋可以怎样继续；错误分类保留 | 不把请求失败显示为无战绩；不会建议绕过隐私 |
| 文本回退 | 与图片同样的结果顺序、来源和完整字段；现有1400字符分段 | 渲染失败用同次结果，不重查、不重复发成功图片 |
| 宿主配置说明 | 数据连接、图片与素材、订阅播报、维护四组；解释字段的用途 | 沿用现有GsCore／AstrBot配置能力，不虚构新控制台 |
| README／商店／图标 | 先列四个实际功能与三步上手；截图只用审查过的实机图 | 现有主宰圆形图标保留，字标／封面同步主题；图标改版另出候选 |

本轮样图展示主要层级及风格，近期样稿省略开始时间／时长，报告表现列表只放排名摘要，队页部分辅助字段使用未知。这些是样稿覆盖限制，实施时不得删除现有数据：近期比赛ID、开始与时长；报告完整正负表现依据；队页现行所有指标；超长名字／ID；权限管理、全套订阅状态和文字回退仍须逐项验证。没有将预览脚本接入生产或修改公开契约。

## 功能文案原则与完整命令

先写用户目的，再写具体命令，每项只解释一件事。用“查最近战绩”替代“数据检索能力”，用“来源未提供”替代不明确的“异常”。图片里的命令行是说明，不是按钮。

| 用户目的 | 命令示例 | 一句话说明 |
| --- | --- | --- |
| 第一次绑定 | `do绑定 <ID>` | 绑定后查自己不用再输入ID；只是查询偏好 |
| 查账号／换绑／解绑 | `do账号` / `do改绑 <ID>` / `do解绑` | 查看或修改当前查询账号 |
| 查自己／别人段位 | `do查询` / `do查询 <ID>` | 看段位徽章与预估MMR区间 |
| 查最近20场 | `do战绩 20` | 默认10场，可选1–100场 |
| 查别人战绩 | `do战绩 <ID> 20` | 一个参数是条数，指定账号须同时给条数 |
| 翻页／选择比赛 | `do战绩 第3页` / `do比赛 第1场` | 使用同次已发送列表的页码／绝对序号 |
| 直接看历史比赛 | `do比赛 <比赛ID>` | 比赛ID独立于玩家ID，无需先查近期 |
| 查热门出装 | `do主宰出装` / `doAM出装` / `do出装 Shadow Fiend` | 支持全名与别名，有歧义给候选 |
| 订阅／取消 | `do订阅玩家 <ID>` / `do订阅比赛 <比赛ID>` / `do订阅列表` / `do取消订阅 <订阅ID>` | 默认关闭，群创建由Bot管理员操作 |
| 通知偏好／人工重试 | `do订阅 段位` / `do订阅 日报` / `do重试推送 <事件ID>` | 有限观察；重试前核实是否送达，可能重复 |

AstrBot是否添加 `/` 依实际唤醒前缀，公共图上不硬编码平台前缀。管理员命令仅按可信权限及宿主实现展示，普通菜单不塞配置字段。

## 样图与来源

[预览脚本](render_previews.py)在仓库根目录执行 `uv run --locked python .agents/artifacts/theme-redesign-v3/render_previews.py`。仅读取既有本地素材与字体，预览保存在被忽略的 `.dota2forge-assets/previews-theme-v3/`，不加入wheel、不作为MIT素材提交。

三张提案板：`proposal-main.png`、`proposal-components.png`、`proposal-reports.png`。七张独立样图：`menu.png`、`player.png`、`recent.png`、`hero-items.png`、`match-overview.png`、`match-team.png`、`components.png`；780px样图同时生成390px检查图。

背景 `forge-atmosphere.png` 为内置image_gen原创无字遗迹／锻炉装饰，原稿保留2172×724，工具未返回模型名。[生成记录](generation.json)保存提示词／来源摘要。英雄、装备、段位用现有按ID素材；沿用[素材边界](../../../docs/cookbook/illustrations.md)，图标不由AI重新生成。字体Noto为OFL；样稿品牌字标使用本机Georgia，未复制字体文件；生产阶段须选择可分发字体或继续现有字体。

## 检查与实施接续

自动尺寸／2MiB／文字边界／文字重叠结果见[检查记录](render-checks.json)。人工检查常规390px图片和完整比赛报告通过。统一离线入口exit0：2009项禁网测试，1项pytest-socket告警（测试DNS解析尝试已被禁网机制拦截），Ruff/mypy86文件通过，覆盖92.49%，scripts/Core/Assets分别94%/93%/93%；[完整日志](offline-check.log)。首轮因生成记录尚未落盘而被链接检查拒绝，补齐后重跑通过。预览不证明宿主消息递送或客户端压缩已通过。

认可方向后分三步实施：先提取共享主题及标题／来源／命令／状态组件，再迁移常规卡和双端文字，最后迁移宽报告／通知／帮助文档。保持现有Card输入与来源语义，若确需新公共接口再附独立note并核查全部消费者。管理员权限、订阅投递、来源故障、素材缺失、长内容与真实聊天逐项验收。
