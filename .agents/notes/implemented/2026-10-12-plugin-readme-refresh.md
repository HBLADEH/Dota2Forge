# 双端 README 与发行文档链接整理

Category: operations
Related task: [README 任务](../../tasks/done/2026-10-12-plugin-readme-refresh.md)
Related code: [分发生成器](../../../scripts/build_plugin_distributions.py)
Related docs: [截图清单](../../../docs/cookbook/plugin-showcase.md)

## Problem
两端 README 混入多轮版本和历史宿主记录，旧安装/截图清单与当前后台配置、三页比赛报告不一致。生成器依赖带装饰的标题，公开分发会把所有主仓操作文档链接替换为 INSTALL.md；新加入的更新日志链接还需适配 AstrBot Cloud。

## Decision
两端统一为功能、效果、安装、快速开始、命令、配置、数据说明、更新与许可的结构。版本与历史证据留在既有发行/宿主文档，不更改其记录。保留旧主宰图原字节、宿主及日期，不将旧主题图宣称为新主题或 GsCore 实机证据。

分发生成器同步普通 Markdown 标题，继续只替换一个安装节；随包安装明确保存后先停用再重载，薄分发使用宿主解释器安装，不引导调用随包管理命令。公开薄分发仅将对应安装指南链接转换到 INSTALL.md，其余文档继续指向固定 source_ref，AstrBot 的 CHANGELOG.md 转为目标仓库完整地址以供 Cloud 使用。版本、依赖、白名单、摘要、大小与禁止覆盖规则保留。

截图计划为七张共享功能卡及两端各一张配置页，绑定/分页/订阅为可选。当前战绩无装备，比赛总览与两队三页来自同一次查询；来源缺失和未知说明不删。

## Alternatives considered
保留装饰标题以适应旧替换规则会限制 README 排版；同步标题常量并保留缺节失败更明确。删除旧图会失去唯一已审查展示，因此保留历史标注，等待用户补新图。仅改源码文档会遗漏 Cloud 更新日志和打包导航，故同时核对生成结果。

## Consequences
只调整文档及其分发呈现，不改业务、宿主环境、配置、数据或平台权限；不公开发布。已有验证中的版本/商店历史字样改为当前 M0、字段解释与导航契约，保留图片来源、ZIP、摘要、本地链接和缺节失败断言。真实截图、主动推送和其他平台仍需用户验收。

## Verification
最终统一离线2013项测试、Ruff/mypy、治理链接和全部覆盖率门槛通过；双端v3候选生成和本地隔离安装通过。首轮旧导航断言两项失败，按新规则明确验证本地安装页与源码文档去向后完整复测通过；没有删除隐私/摘要/大小/覆盖率断言，也没有修改 policy、工作流或治理检查器。实际命令及未验收项见关联任务。
